## 제품 결정

OpenRhiza는 기능을 안전하게 확보·구현·실행·교체·개선하는 독립적인 AI 기반 범용 운영체제입니다.
기반은 독립적으로 검토하는 작은 커널이며, 상위 동작은 모두 샌드박스 모듈로 구성합니다.
AI는 의도를 해석하고 구현을 생성하며, 권한은 모델 밖의 결정적인 기구가 강제합니다.

Linux 배포판, 다른 OS 위의 에이전트, 클라우드 의존 단말, 커널 내부 인터프리터 데모,
동작하는 앱처럼 보이기만 하는 패널 모음이 목표가 아닙니다.
엣지·IoT와 상업용 샌드박스 서비스는 향후 활용처일 수 있지만 주목표를 바꾸지 않습니다.

"0에서 시작"은 자체 소스·인터페이스·빌드·시험을 새로 만든다는 뜻입니다.
기존 코드는 관찰과 참고 자료로 남깁니다. 표준과 독립적으로 검토한 이식 가능한 라이브러리는 허용합니다.
이는 공학적 재시작이며 법적으로 독립된 클린룸 개발임을 주장하는 것은 아닙니다.

## 반드시 유지할 원칙

- Linux/BSD/Windows/Android 커널이나 다른 OS 서비스 없이 부팅하고 실행합니다.
- 커널 코드는 Rhiza Core뿐입니다. 일반 복구 UI, 드라이버, VFS·파일시스템, 프로토콜, Wasm 런타임,
  화면 합성기, 앱, 음성, 모델 클라이언트, 서비스 감독자, 정책, 모듈 탐색·선택은 격리 모듈입니다.
- 명시된 장애 모델 안에서 모듈 장애·무한 루프·자원 폭주·런타임 결함이 코어 손상, 패닉, 실행 기아, 재부팅을 일으키면 안 됩니다.
- 모듈에는 명시적인 객체 권한(capability)을 부여합니다. 파일·네트워크·화면·입력·장치·모델·서명·관리 권한이 암묵적으로 주어지지 않습니다.
- 설치된 기능의 일반 실행 경로에는 모델 추론이나 레지스트리 접근이 필수여서는 안 됩니다. 오프라인 부팅·복구를 유지합니다.
- 모델 출력과 검색된 모든 내용은 비신뢰 입력입니다. 생성·평가·서명·배포·로컬 허가는 각각 분리된 책임입니다.
- 사용자의 통제권이 우선합니다. 자율 모드에서도 되돌릴 수 없거나 파괴적인 변경과 비공개 자료 공개는 명시적 정책·승인을 따릅니다.
- 공개 주장은 해당 산출물에 대한 재현 가능한 실제 동작·실패 근거가 필요합니다. 이름·플래그·투표·로그만으로 완료를 인정하지 않습니다.

## Rhiza Core의 경계

코어는 CPU 권한 전환, 주소 공간, 보호된 스택, 물리·가상 메모리, 타이머 선점, 스레드·프로세스 수명주기,
객체 권한 표, 제한된 IPC, 인터럽트 라우팅, 제한된 장치·DMA 중재를 담당합니다.
여기에 최소 초기 진단과 승인된 복구 집합만 실행하는 기구를 둡니다.
일반 명령 파서, 장치별 프로토콜, GUI 객체 렌더러, 파일시스템 형식, TLS 클라이언트, 모델 프롬프트,
패키지 작업 절차는 커널에 넣지 않습니다.

서명된 초기 이미지는 명시적 권한을 가진 사용자 모드 부트스트랩·복구 모듈을 제공합니다.
권한과 예약 자원은 드러나 있어 검토할 수 있어야 합니다. 같은 이미지에 포장됐다고 커널 코드가 되는 것은 아닙니다.
감독자가 실패하면 커널은 고정된 승인 복구 집합을 다시 실행할 수 있습니다.
신뢰할 복구 구현을 LLM에게 결정하게 하지 않습니다.

실제 신뢰 기반(TCB)에는 펌웨어·부트 검증, 커널 구현, 초기 특권 모듈, 키, 빌드·릴리스 도구가 포함됩니다.
커널 소스 크기만 설명해 이 의존성을 숨기지 않습니다.

커널 진입 코드를 구현하기 전에 K 계약에서 외부 이미지 신뢰 기준, 검증기·파서 소유권, 첫 사용자 권한 주체,
최대 권한, 부팅 메모리 소유권을 명시합니다. 모듈 허가 전에 코드뿐 아니라 권한을 결정하는 설정도 인증합니다.
초기 진단 부팅은 명시적으로 호스트를 신뢰하는 이미지를 사용할 수 있지만, 검증 부팅이나 물리적 보안을 입증하지는 않습니다.
크기·범위를 제한한 부트 인계는 상주 이미지·페이지 테이블·펌웨어 예약 영역을 보존하고,
펌웨어 종료와 종료 후 콘솔 규칙을 정의해야 합니다.

복구에 필요한 의존성 전체는 상주해야 하고, CPU·프레임·객체 슬롯·큐·진단 자원을 일반 권한으로 제거할 수 없도록 예약합니다.
초기 격리 콘솔은 일반 감독자·GUI·저장소·네트워크·AI에 의존하지 않습니다.
고정 집합의 재실행에는 횟수 제한과 명확한 기능 저하 결과가 있어야 합니다.
공유 서비스 복구 중 종속 클라이언트에는 제한된 시간 안에 오류를 반환할 수 있지만,
관계없는 유용한 작업과 예약된 복구 경로는 계속 동작해야 합니다.
일반 특권 모듈의 충돌은 장애 모델에 포함합니다. 명시적으로 신뢰하는 권한·키 정책의 침해는 별도 가정입니다.

## 격리와 생존 계약

단일 코어에서 보호된 사용자 실행과 선점부터 시작합니다. 생성된 장치·서비스 코드를 도입하기 전에
Wasm 해석·JIT·AOT와 호스트 함수 중개기를 격리된 사용자 작업자로 옮깁니다.
네이티브 ELF 모듈도 보호된 사용자 프로세스와 동일한 매니페스트·권한·수명주기 규칙을 사용합니다.
Wasm은 이식 가능한 실행 형식이며, 유일한 샌드박스나 하드웨어 격리의 대체물이 아닙니다.
모든 위젯을 프로세스로 만들 필요는 없습니다. 앱 내부 효과는 객체 범위로 제한하고,
독립적인 권한·장애 영역은 별도 작업자로 나눕니다.

커널의 실행 허가 검사는 크기 제한, 검사된 산술, 실패를 반환하는 할당, 세대 번호 핸들,
권한 철회, 큐 한도, 사용자 메모리 복사를 사용합니다.
커널 잠금이나 IRQ 임계 구역을 잡은 채 모듈 콜백을 실행하지 않습니다.
Wasm 연산 예산인 fuel만으로 대기하는 호스트 호출을 제한할 수 없습니다.
선점·기한·제한된 IPC가 모듈의 협조와 무관하게 종료·진행을 강제해야 합니다.

커널 메타데이터, 위임된 서비스 작업, 공유 권한, 정리 작업을 포함한 모든 자원에는 비용 부담 주체와 한도가 있습니다.
객체 공개 전에 사용량을 차감하고 클라이언트가 죽어도 정리 예산은 남깁니다.
논리적 철회는 새로운 접근을 막습니다. 물리적 회수는 이미 허용한 작업·참조와 필요한 CPU/DMA 무효화 완료를 기다립니다.
세대 번호만으로 재사용이 안전하다고 가정하지 말고 핸들 폐기와 철회 완료 조건을 정의합니다.

네이티브 시스템 호출·수명주기 계약에는 작업량 한도, 불변 요청 스냅샷, 사용자 메모리 복사 오류,
큐 오류, 권한 이전, 기한, 상대 프로세스 종료, 효과 확정 후 취소를 정의합니다.
제한된 비동기 요청·응답을 우선하며, 동기 경로는 우선순위·예산 역전의 상한을 입증해야 합니다.
네이티브 진입·복귀와 활성화한 모든 스레드별 아키텍처 상태를 시험합니다.
구현한 부분집합이 정상 왕복·장애 시험을 통과할 때까지 ABI를 실험 상태로 유지합니다.

DMA 드라이버에는 강제 가능한 장치 격리와 리셋·정지 계약이 필요합니다.
D가 정확한 요청자·주소 변환·MMIO·인터럽트·타이머·리셋 환경을 검증하기 전에는 일반 장치 권한을 거부합니다.
초기 비-DMA 콘솔은 별도로 검증한 좁은 권한 계약을 갖습니다.
IOMMU 존재 플래그만으로 격리를 입증할 수 없으며, QEMU의 호스트 격리가 무제한 에뮬레이트 DMA로부터 게스트 코어를 보호하지 않습니다.
리셋·진행 중 접근 종료가 실패하면 안전성이 확인되지 않은 페이지를 정해진 예산 안에 격리하고 재사용하지 않습니다.
검증되지 않은 생성 드라이버의 하드웨어 실험은 폐기 가능한 에뮬레이터의 명시적인 신뢰 드라이버 실험이며,
적대적 드라이버 격리 근거가 아닙니다. 물리 고장·펌웨어 결함·가정 밖 하드웨어는 절대 무충돌 주장에 포함하지 않습니다.
허용된 정상 규격 장치의 악의적 사용은 선택한 장치 장애 모델에 포함합니다.

생존 근거에는 같은 부팅 식별자, 독립 관찰 작업의 진행, 제한 시간 안의 복구 응답, 장애 후 자원 회수가 필요합니다.
watchdog 재부팅은 복구 근거이며 동일 코어 생존 조건에서는 실패입니다.
형식·모델 검증, 퍼징, 장애 주입, 장시간 시험은 서로 보완하지만 시험 통과만으로 모든 커널 결함의 부재를 증명할 수 없습니다.

각 수락시험 전에 환경별 한도, 지연·회수 기한, 반복 횟수, 허용 자원 여유를 확정합니다.
독립적이고 보호된 확인 요청 채널과 호스트 단조 시계의 기한으로 유용한 작업·부팅·리셋 상태를 검증합니다.
후보 모듈이 쓴 성공 로그로 통과를 인증하지 않습니다.
일부러 고장 낸 대조군을 통해 판정기가 진행 중단·리셋·손상을 거부하는지 보여야 합니다.

## 로컬 기능 수명주기

```text
사용자 의도 + 로컬 상태
  -> 승인된 로컬 캐시 -> 레지스트리 호환성·근거 조회
  -> 재사용 또는 예산이 제한된 AI 소스 생성
  -> 버전을 고정한 격리 빌드 + 독립 분석·계약·적대적 시험
  -> 승인된 불변 해시 + 서명된 매니페스트 + 릴리스 채널
  -> 로컬 정책 + 객체 권한·자원 허가
  -> 샌드박스 시험 배치 + 장치·서비스 정지 + 버전별 상태 이전
  -> 상태 확인 + 실행 연결의 원자적 확정
  -> 다음 부팅 선호 상태 저장 또는 권한 철회·정지·롤백
  -> 동의와 민감정보 제거를 거친 정확한 산출물·플랫폼별 평가
```

패키지 식별자는 파일 슬롯이나 GUI 번호가 아닙니다. 스키마·버전, 산출물 해시, 실행 환경, 인터페이스,
의존성 해시, 플랫폼·장치 일치 조건, 요청 권한, 예산, 상태 스키마, 롤백 대상, 라이선스, 출처,
독립 시험 근거, 서명자, 채널, 철회 상태를 정의합니다.
K에서는 초기 부트 형식과 제한된 시험 자료만 확정합니다. 나머지 매니페스트·네이티브 ABI 부분집합은
정상·비정상 왕복 동작을 검증할 때까지 버전이 있는 실험 상태로 두며, 알 수 없는 권한 필드는 거부합니다.
범용 IDL 도구체인은 첫 부팅의 필수 조건이 아닙니다.

현재 실행 상태와 다음 부팅 선호 상태는 별도 트랜잭션입니다.
데이터 이전과 되돌릴 수 없는 장치 효과에는 명시적인 호환성·롤백 정책이 필요합니다.
코어 업데이트는 독립 검토된 서명 시스템 이미지를 사용합니다. AI의 커널 메모리 즉시 패치는 일반 기능이 아닙니다.

실제 전환 전에 작업 세대, 실행 연결 확정 시점, 중단 시 허용 상태를 정의합니다.
새 쓰기 주체에 권한을 주기 전에 기존 소유자의 새 작업을 차단하고 진행 중 작업을 종료합니다.
초기에는 호환 스키마 또는 명시적 백업·복원만 허용하며 위험한 이전은 거부합니다.
파일·선호 상태의 영속 완료 응답에는 블록·캐시 장애 모델과 호스트가 보유한 예상 상태 판정기가 필요합니다.
재부팅만으로 전원 손실을 시험할 수 없습니다. 최소 신뢰 상태 복구는 3단계 실행 허가 전에 갖추고,
시스템 이미지 A/B 인증과 릴리스 운영 훈련은 6단계에 둡니다.

설치된 산출물은 로컬에서 철회되지 않았다면 마지막으로 수락한 권한을 유지합니다.
메타데이터 최신성이 불명확하거나 오래되면 신규 허가·권한 확대를 막되, 승인된 설치 기능과 고정 복구는 유지합니다.
오프라인 노드는 받지 못한 철회 정보를 알 수 없습니다.
승인된 롤백이 옛 신뢰 정보를 재사용하지 않도록 보안 세대와 코드 버전을 구분합니다.
TLS·키 생성 전에 신뢰할 실제 시각의 초기화와 엔트로피 실패 동작을 정합니다. 코어 단조 시간 기한은 둘에 의존하지 않습니다.
악의적인 디스크 롤백 저항에는 독립 최신성 기준점이 필요하며, 없으면 초기 범위에서 명시적으로 제외합니다.

## 입력과 사용자 경험

기본 세션은 유용한 명령 터미널입니다. 정확히 등록된 명령은 타입이 정해진 작업을 통해 로컬 실행합니다.
알 수 없거나 모호하거나 여러 단계인 요청은 교체 가능한 모델 계획기로 보냅니다.
어떤 서비스가 효과를 내기 전에 계획은 결정적 권한 검사, 필요한 확인, 취소, 감사, 되돌리기·트랜잭션 경계를 통과합니다.

로컬 타입 명령·작업의 최소 집합은 2단계 터미널에서 시작하며, 5단계는 같은 권한 기구에 모델 계획을 추가합니다.
효과는 권한 주체·객체 권한·객체 세대·인자·정책 세대·승인 범위·기한·트랜잭션 ID에 연결합니다.
확정 시 다시 검증하거나 예약으로 승인 조건을 유지합니다.
신뢰된 확인 화면은 검증된 효과를 표시합니다. 모델 문장·패키지·캐시 워크플로·오래된 의미 색인 권한 판단이 승인을 대신할 수 없습니다.

입력 모듈이 포커스·포인터 캡처를 포함한 키보드·포인터 이벤트를 정규화합니다.
UTF-8, 한·영 렌더링, IME, 조합, 선택, 줄바꿈, 접근성 텍스트는 텍스트 서비스의 책임입니다.
음성은 사용자가 선택하고 녹음 상태가 보이는 캡처·VAD·ASR·전사문 확인 경로를 같은 의도 라우터에 추가합니다.
기본 꺼짐·누르고 말하기를 먼저 제공하고, 상시 청취·직접 멀티모달 음성은 나중에 다룹니다.
백그라운드 에이전트가 스스로 마이크를 켤 수 없습니다.

네이티브 데스크톱은 독립 앱의 화면 표면, 포커스, 이동·크기 변경, 닫기·최소화·최대화, 작업 공간,
클립보드, 알림, 작업 전환을 제공합니다. MDI·문서 창과 백그라운드 작업은 실제 클라이언트 상태입니다.
전경 QoS는 게임 프레임 카운터를 높이려고 나머지를 중단하지 않고 복구와 다른 허가된 서비스의 예산을 보존합니다.
AI가 편집하는 GUI 장면은 합성기 위의 제한된 객체 작업을 사용하며, 임의의 커널 렌더링 함수를 노출하지 않습니다.

초기 앱은 터미널·LLM, 파일, 설정, 모니터, 모듈 관리자입니다.
실제 Doom/FreeDoom 모듈로 설치, 포커스에 맞는 키보드·마우스, 게임 시간, 화면, 소리, 영속 저장,
백그라운드 동작, 오프라인 재실행, 충돌 격리를 시험합니다.
게임 전용 커널 ABI, WAD 파서, 게임 루프, 저장 우회 코드는 허용하지 않습니다.

## Nexus와 모듈 제작

OpenRhiza.com은 공유 운영 지식 기반입니다. 드라이버·서비스·앱·스킬·호환 런타임·모델·자산을
워크플로, 정책, 노드, 하드웨어·플랫폼 기록, 산출물별 평가, 댓글, 투표, 출처, 릴리스 이력과 통합합니다.
사람용 게시판과 기계 API는 같은 데이터 모델을 사용하며 공개·비공개 표현을 구분합니다.

레지스트리, 모델 게이트웨이, 제작 작업자, 독립 검증자, 승인, 릴리스 서명을 분리합니다.
작성자·노드를 인증하고 키 소유를 입증해야 하며, TPM 신뢰에는 검증된 증명이 필요합니다.
기여물은 즉시 활성화하지 않고 격리 상태에서 시작합니다. 스키마·크기·할당량·기한·남용 방지·최소 권한을 적용합니다.
투표와 LLM 분석은 후보 검색·우선순위에 도움을 줄 뿐 필수 시험·권한·호환성·철회 검사를 대체하지 않습니다.

초기 클라우드 서비스는 일반 서버 인프라를 사용할 수 있습니다. 이는 OpenRhiza 게스트의 OS 의존성이 아닙니다.
향후 OpenRhiza 자체에서 서비스를 호스팅하는 것은 자가 개발 이정표이며, 독립 OS 초기 사용의 선행 조건은 아닙니다.
모델 제공자는 사용자가 선택·교체합니다. Gemini나 특정 모델이 커널 아키텍처가 되지 않습니다.
커널 이미지·공개 패키지에 사용자 API 키를 포함하지 않습니다. 비밀정보 접근은 부여된 모듈 권한으로 제어합니다.

## 비공개 지식과 자율 동작

관리 파일이 원본 데이터입니다. 다시 만들 수 있는 별도 의미 색인이 콘텐츠 식별자·해시, 청크, 요약,
개체, 관계, 최신성을 저장합니다. 질의는 호출 사용자 권한을 따르고 작은 참조를 반환합니다.
원문 읽기·업로드는 별도 허가 작업이며, 파일 이벤트로 제한된 갱신을 수행합니다.
그래프 자체가 필수 새 파일시스템이 되는 것은 아닙니다.

꺼짐·보조·협의(off/assist/council) 모드는 사용자가 제어합니다.
독립 제안·근거·이견·제한된 작업으로 계획을 개선하되 다수결이 권한이나 정확성을 만들지 않습니다.
타이머·모델 장애·자원 제한 때문에 사용자 세션을 사용할 수 없게 되어서는 안 됩니다.
진단·방화벽·포렌식은 실제 권한 기반 앱으로 구현합니다.
허가된 프로세스 덤프 검사와 무제한 커널 메모리 패치는 구분합니다.

## 범위와 장기 확장

첫 지원 환경은 버전·설정이 고정된 x86_64 QEMU 환경 하나입니다.
UEFI, VirtIO, 소프트웨어 합성을 우선 검토하고 1단계에서 펌웨어·도구체인·장치 선택을 검증한 뒤 확정합니다.
자체 쓰기 가능 파일시스템은 사용자 데이터를 저장하기 전에 내구성·전원 손실 조건을 통과해야 합니다.
FAT 전송·부팅과 외부 파일시스템 읽기·가져오기 모듈은 역할이 다릅니다.

자가 SDK·컴파일러·빌드·시험, 선택적 로컬 추론·가속, 네이티브 브라우저·연구 도구, 폭넓은 파일시스템 상호운용,
검증된 실제 PC 한 대, ARM64 QEMU·보드, RISC-V, 특정 잠금 해제 폰, Wi-Fi·Bluetooth·USB 테더링,
제조사 그래픽, 외부 프로그램·Wayland 호환성은 계속 로드맵에 포함합니다.
각 항목은 별도 근거가 필요한 모듈·기능 과제입니다. 알파에서 보편적 하드웨어·프로그램 호환성을 주장하지 않습니다.

공개 릴리스는 명시한 범위에서 격리·기능·내구성·공급망·복구·개인정보·장시간 시험을 통과해야 합니다.
소스 공개나 동작하는 데모만으로 안전한 공개 OS가 되는 것은 아닙니다.
