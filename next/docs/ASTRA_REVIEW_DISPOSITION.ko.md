# Astra 계획 검토 반영 내역

[영문 원문](ASTRA_REVIEW_DISPOSITION.md) · [한국어 목차](../README.ko.md)

날짜: 2026-10-03. 상태: 초기 검토 반영, Astra 계획 재검토 완료.

사용자는 커널 구현 전에 Astra로 검토하고 이후 커널 작업에도 Astra를 사용하도록 요청했습니다.
검토자는 `gpt-6-astra`, 추론 수준 `max`, 에이전트 `01a0ff02-15af-7270-b1dd-37dbd7cbf541`입니다.
지적 사항은 [검토 보고서](ASTRA_PLAN_REVIEW.ko.md)에 있으며, 이 문서는 반영 내역과 수정된 계획의 후속 검토를 기록합니다.
모델 검토는 공학적 근거이며, 무결점 구현의 증명은 아닙니다.

이 번역의 해시와 원문 행 번호는 검토 당시 영문 스냅샷 기준입니다.

## 검증 맥락

반영 전 `tools/verify-baseline.ps1`은 R0 참고 목록 검증을 통과했습니다. 호스트에는 Rust stable/nightly,
QEMU `10.2.0 (v10.2.0-12105-g0f12d445bd)`, EDK2 x86_64 펌웨어 파일이 설치되어 있습니다.
설치 여부는 새 도구체인·펌웨어·머신 구성·커널 이미지의 적합성 검증을 대신하지 않습니다.

기존 x86_64 이미지는 기존 TCG 시험 도구로 `/status`, `/recovery` 기본 동작 시험을 통과했습니다.
직렬 로그에서 두 명령과 복구 진입을 확인했으며, 확인한 출력에는 panic·page-fault·triple-fault 표식이 없었습니다.
근거: `../../logs/x86-astra-plan-review-reference-20261003.log`.
기존 이미지의 참고 근거이며, 새로 부팅할 커널은 아직 없습니다.

## 반영 내역과 준비 상태

초기 검토에서 계획 계약의 공백 P1 8건과 P2 2건을 발견했습니다. P0·P3는 주장하지 않았습니다.
10건 모두 [방향](DIRECTION.ko.md), [착수·통과 기준](IMPLEMENTATION_GATES.ko.md), [로드맵](ROADMAP.ko.md)의
결정·근거 요구로 반영했습니다. 해당 기능 구현이나 향후 통과 조건이 완료됐다는 뜻은 아닙니다.
초기 보고서의 행 번호는 위 해시의 수정 전 문서를 가리키며, 현재 요구는 수정된 기준 문서를 따릅니다.

| 지적 | 계획 변경 | 남은 완료 조건 |
| --- | --- | --- |
| F01 | K에 외부 부트 신뢰, 제한된 인계, 메모리·파서 소유권, 첫 권한 요구 | 1.2단계 전에 K의 ADR·시험 자료 선정·검토; 초기 모듈 실행 전에 이미지 허가 검증 |
| F02 | K/N에 상주 복구 의존성, 보호된 예약 자원, 재시작 제한, 제한된 기능 저하 동작 정의 | K에서 초기 콘솔·권한 경로 선택; N에서 복구 강제·장애 시험 |
| F03 | N에 비용 부담 주체, 메타데이터·위임 자원 계산, 논리적 철회와 물리적 회수·완료 구분 | 적대적 CPU 전용 실행 검증 전에 구체적 원장·상태 기계와 경쟁·재사용 근거; SMP 전에 확장 |
| F04 | N에 시스템 호출·수명주기 결과, 불변 스냅샷, 제한된 요청·응답과 우선순위 역전 규칙 | K에서 첫 ABI 초안; N에서 초기 연산 의미를 구현·시험 |
| F05 | D로 일반 DMA/MMIO/IRQ 권한과 격리를 통제; 초기 비-DMA 콘솔은 별도 검증 | K에서 필요한 환경 선택; 일반 권한이나 적대적 드라이버 격리를 주장하기 전에 D 입증 |
| F06 | A에서 시간·엔트로피, 로컬 허가 최신성·보안 세대와 오프라인 롤백 정책을 외부 허가보다 앞에 배치 | N에서 고정 이미지 신뢰; 3단계의 등록·설치 전에 신뢰 상태 영속화와 실패 시험 |
| F07 | A에 기존 작업 차단, 세대, 실행·영속 상태 확정 시점, 허용 충돌 상태 판정기 요구 | 실제 전환 또는 사용자 데이터 쓰기 전에 구체적인 서비스·저장소 프로토콜 |
| F08 | K에 판정기 소유권; 수락시험표에 한도·기한 고정과 의도적 실패 대조군 | K/1.3에서 시험 도구 검증, 각 수락시험 전에 환경별 수치 보정 |
| F09 | 2단계에 로컬 타입 명령 도입; Intent에서 승인을 주체·객체·버전·확정 시점에 연결 | N에서 로컬 부분집합 강제; 5단계의 효과 발생 전에 승인·재전송·검사/사용 시점 차이 시험 |

그 전에 네트워크 프로토콜을 개발할 수 있지만, 영속적이고 인증된 노드 신원이 확보됐다고 주장할 수 없습니다.

## Astra 재검토 결과

동일한 `gpt-6-astra` 검토자는 수정된 계획을 **1.1단계 K 계약 작업 진행용으로 승인**했고,
진행을 막는 통합 모순을 발견하지 못했습니다. 보고서에 추가한 재검토 절은 F01~F10 반영과 초기 콘솔,
영속 상태를 갖춘 실행 허가, 단일 vCPU·Wasm·SMP의 순서를 확인합니다.
계획 수준의 승인으로, 1.2단계 진입 허가나 구현된 보장은 아닙니다.

Astra는 진행을 막지는 않는 P2 시간 문구 오류 한 곳을 지적했습니다. 자원 회수 시간을
중지·권한 회수 요청 수락 대신 "해제 완료 확인" 이후부터 재는 표현이었습니다.
조정 담당은 재검토 뒤 `IMPLEMENTATION_GATES.md`에 요청된 수정을 적용했습니다.
비동기 해제 전에 보호된 요청 수락을 정의하고, 제출·수락·기준 자원 상태 도달을 따로 기록하며,
요청 지연의 수치 한도와 호스트 전체 시간 제한을 요구합니다.
최종 해제 완료 응답이 측정 시작점을 늦출 수 없습니다. 이는 수치 보정 요구이며 실측 결과가 아닙니다.
보고서의 재검토 해시는 이 직접 지시된 수정과 반영 내역 갱신 이전의 값이며, 과거 스냅샷은 유지합니다.

반영 후 목록 재생성과 `tools/verify-baseline.ps1`이 문서 76개를 포함한 참고 파일 364개에 대해 통과했습니다.
수정한 루트 인계 문서는 `git diff --check`를 통과했습니다.
QEMU 근거는 앞의 기존 이미지 명령·복구 시험이며, 새 이미지를 빌드하거나 실행하지 않았습니다.

1.1단계는 진행할 수 있지만 K의 구체적 선택·시험 자료·진입 검토는 아직 수행하지 않았습니다.
1.2단계 커널 코드, 적대적 네이티브·장치 실행, 공개는 검증되지 않았습니다.
실제 K 산출물의 검토는 수정된 계획의 재검토와 별개입니다.
커널 구현에는 요청된 Astra 모델을 사용하며, 각 단계에서 빌드·QEMU·장애 주입·수정을 수행합니다.
