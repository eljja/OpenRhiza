# Astra 설계 준비도 검토

[English original](ASTRA_PLAN_REVIEW.md) | [한국어 목차](../README.ko.md)

이 문서는 Astra 검토 보고서의 한국어 전문입니다. 새로운 독립 검토 결과가 아닙니다.
아래의 초기 `PENDING` 판정은 당시 기록이며, 이후 결과는 문서 후반의
**계획 반영 재검토**와 [검토 반영 내역](ASTRA_REVIEW_DISPOSITION.ko.md)을 참고하세요.
근거의 행 번호와 SHA-256은 한국어본이 아니라 해당 검토 시점의 영문 원문을 가리킵니다.

날짜: 2026-10-03 (Asia/Seoul).
검토자: 사용자가 명시적으로 요청한 실제 `gpt-6-astra` 에이전트.
검토자 신원은 현재 로컬 세션의 `turn_context.model = gpt-6-astra` 메타데이터
(2026-10-02T23:45:23.719Z, 추론 강도 `max`)로 확인했습니다.
단지 요청받은 역할을 근거로 모델을 추정하지 않았습니다.

범위: 새 커널 구현 이전, 재시작 기준점 R0에서의 문서 검토 증거.
`next/README.md`, `DIRECTION.md`, `REQUIREMENTS.md`, `LEGACY_REVIEW.md`,
`ROADMAP.md` 전체와 이를 뒷받침하는 메타데이터 검증기를 읽었습니다.
좁은 기술적 질문에 대해서는 아래에 연결한 1차 명세를 참고했습니다.
다른 에이전트 사용, 새 런타임 코드 작성, 소스 이동, 빌드, 배포, 커밋,
유료 외부 모델 호출, 다른 대화로의 메시지 전송은 수행하지 않았습니다.

제안 판정: **CONDITIONAL(조건부)**. 1.1단계의 환경 적격성 확인과 계약 정의는
진행하되, 이 기준 문서만으로 1.1단계 완료를 선언하거나 1.2단계에 착수하지 않습니다.
방향은 일관되지만, 아직 구현 진입을 허용하는 계약은 아닙니다.
후속 적대적 실행·장치·출시 단계의 선행 조건 전체를 최초 진단 부팅의 선행 조건으로
만들어서도 안 됩니다.

반영 상태: **PENDING(대기)**. 주 작업에서 공식 기준 문서에 반영해야 합니다.
재검토 상태: **PENDING(대기)**. 문서 변경과 1.1단계 의사결정 이후에 수행합니다.
이 검토로 새 OS의 어떤 단계도 통과하지 않습니다. 사용자의 요청에 따라 향후 커널
구현 담당은 Astra로 유지됩니다. 이 보고서는 그 구현을 시작하거나 다른 대화의 모델
선택을 변경하지 않습니다.

## 발견 사항

아래는 설계 계약의 구체적인 공백입니다. 아직 존재하지 않는 새 커널 코드에서 관찰한
버그가 아닙니다. 실패 시나리오는 인용한 계획에 대한 검토자의 추론입니다.
P1은 표시한 신뢰 경계를 넘기 전에 해결해야 한다는 뜻이고, P2는 범위가 제한된 순서
또는 계약 수정입니다. P0나 P3를 주장하지 않습니다. 특히 이 검토는 수정 불가능한
구조적 모순의 증거도, 안전한 런타임의 증거도 아닙니다.

### F01 - 부트스트랩 신뢰와 메모리 소유권의 구체적인 인계 필요

근거: 영문 [DIRECTION.md](DIRECTION.md) 47·55행, [ROADMAP.md](ROADMAP.md) 26·157행.
계획은 감사 가능한 부팅 계약과 더 넓은 신뢰 컴퓨팅 기반(TCB)을 올바르게 요구하지만,
누가 무엇을 인증하는지, 최초 권한은 누가 만드는지, 진입 후 어떤 부팅 할당 영역의
소유권이 유지되는지는 아직 선택하지 않았습니다.

실패 시나리오와 결과: 이미지와 함께 교체할 수 있는 키로 이미지에 서명해 겉으로는
유효한 복구 모듈을 제공하거나, 할당기가 초기 모듈·페이지 테이블·펌웨어 런타임 데이터가
남은 페이지를 재사용할 수 있습니다. 전자는 복구의 진위 검증을 순환 논리로 만들고,
후자는 사용자 격리 이전부터 코어 소유권의 기반을 무너뜨립니다.

범위를 제한한 수정: 커널에 범용 패키지 관리자를 넣는 대신 부팅/TCB 아키텍처 결정
기록(ADR) 하나를 작성합니다. 신뢰하는 QEMU 호스트·펌웨어·로더 가정, 이미지 밖의
신뢰 루트, 권한 부여·설정을 포함한 검증 대상 바이트, 최초 사용자 주체와 권한 상한,
TCB에 포함되는 로더·검증기·파서를 명시합니다. 버전이 있는 인계 계약에 제한된 길이,
겹침 검사를 마친 영역, 예약 영역, 진입 상태, 스택·페이지 테이블 소유권, 변경 불가능한
상주 초기 이미지 설명자를 정의합니다. 초기 ELF/이미지 파싱 담당을 선택하고, 이후
비신뢰 ELF 로딩이 이 신뢰 파서의 범위를 조용히 확장하지 못하게 합니다.

UEFI에서는 메모리 맵/ExitBootServices 전환을 검증해야 합니다. 전환 후에도 펌웨어
부팅 콘솔 서비스를 계속 쓰는 방식은 안 됩니다. UEFI는 현재 맵 키를 요구하고 성공적인
종료 이후 부팅 서비스 호출을 금지합니다. 이는 제안한 인계의 구체적인 제약이지,
새 펌웨어를 구현하라는 요구가 아닙니다.
[UEFI 2.10, 7.2.3·7.4.6절](https://uefi.org/specs/UEFI/2.10/07_Services_Boot_Services.html?highlight=exitbootservice)

단계/판정: 1.2 이전에 ADR을 확정합니다. 검증 부팅 및 물리적 공격자에 대한 보장을
명시적으로 제외한 신뢰 호스트의 개발 이미지는 초기 구동에 허용됩니다. EDK2가 설치되어
있다는 사실은 이미지 인증의 증거가 아닙니다. 2단계 모듈 실행 전에는 잘못되거나 겹치는
인계 영역, 변경된 이미지·권한 바이트를 선택한 검증기로 시험합니다. TPM 등록이나
6단계 전체 출시 서비스는 진단 부팅의 선행 조건이 아닙니다.

### F02 - 복구 예약에는 의존 그래프와 권한 상한이 필요

근거: 영문 [DIRECTION.md](DIRECTION.md) 29·55·87행, [ROADMAP.md](ROADMAP.md) 49행.
예약 예산과 봉인된 재실행은 타당하지만, 복구 구성 집합, 모든 간접 의존성, 재시작 한도,
회수할 수 없는 최소 권한은 정의되어 있지 않습니다.

실패 시나리오와 결과: 고장 난 감독자가 유일한 콘솔 종단점이나 할당기 할당량을 소유할
수 있고, 복구 실행 파일에 고장 난 파일 시스템을 통해서만 접근할 수도 있습니다.
또는 반복 충돌과 재실행이 프로세스·핸들 풀을 소진합니다. 코어의 틱은 계속되어도
사용자는 복구할 수 없습니다. 복구가 반응하는 것처럼 보이도록 모든 앱을 정지시키는
것도 명시된 지속 진행 요구를 충족하지 못합니다.

수정: 작은 상주 복구 의존 집합을 열거하고, 승인 시 CPU·프레임·커널 객체 슬롯·큐·진단
용량을 예약합니다. 초기 QEMU 프로파일에는 사용자 모듈의 독립적인 직렬 입출력 경로를
선택합니다. 이를 시작하는 데 미래 GUI·네트워크·모델·가변 캐시·정상 감독자에 의존하지
않습니다. 코어에는 고정 집합 재실행, 예약, capability 권한 상한 기제만 둡니다.
재시작·재시도 간격 정책에 한도를 두고, 복구 예산 소진 시 명확한 기능 저하 결과를
반환하는 대체 경로를 정의합니다. 무한 재실행이나 재부팅 후의 성공을 생존으로
표시해서는 안 됩니다.

세 가정을 구별합니다. 일반 모듈은 결함이 있거나 비신뢰 상태일 수 있습니다.
특권 모듈의 권한은 엄격히 제한됩니다. 승인·키 정책 로직은 신뢰합니다.
승인 모듈이 침해되면 인가 보장이 무효가 될 수 있지만, 모든 특권 모듈을 신뢰한다고
부르는 것으로 일반 감독자나 드라이버 충돌을 시험에서 제외해서는 안 됩니다.
최대 권한으로도 제거할 수 없는 코어·복구 예약을 명시합니다. 영향받는 앱의 의존성을
정의합니다. 고장 난 공용 서비스는 제한 시간 안에 오류를 반환할 수 있지만, 관계없는
계산과 복구 경로는 계속 진행해야 합니다. 교체 중인 고장 서비스 자체의 상시 가용성까지
약속하지는 않습니다.

단계/시험: 1.1에서 의존성·권한 개요를 작성합니다. 2단계 적대적 시험 관문 전에는 일반
풀을 포화시키고 감독자와 정상 로거·콘솔 경로를 충돌시킵니다. F08의 시간 제한과 변하지
않은 부팅 식별자 아래에서 복구 명령과 관계없는 작업을 독립적으로 실행합니다.
저장소·컴포지터 도입 후에는 해당 의존성 고장으로 반복합니다.

### F03 - 비용 부담자, 권한 회수가 막는 동작, 메모리 재사용 시점 정의

근거: 영문 [DIRECTION.md](DIRECTION.md) 75행, [ROADMAP.md](ROADMAP.md) 47·54행.
세대 번호 핸들, 할당량, 자원 반환을 나열했지만 소유권과 완료 의미론이 없습니다.

실패 시나리오와 결과: 작은 사용자 할당이 큰 커널 매핑·핸들·IPC 메타데이터를 만들거나,
죽는 프로세스가 공유 권한의 비용 부담자를 없애거나, 진행 중인 연산 또는 오래된 CPU
주소 변환이 여전히 쓰는 프레임을 다른 주체에게 반환할 수 있습니다. 단일 코어의 선점과
인터럽트만으로도 이런 실행 교차에 대한 결정이 필요합니다. 전부 SMP까지 미룰 수 없습니다.

수정: 작은 자원 원장을 2단계 계약에 포함합니다. 확정 할당 페이지, 페이지 테이블,
보호된 스택, 프로세스·스레드, 핸들, 대기 바이트·권한, 공유·고정 버퍼, 결함·로그 기록,
정리 작업의 비용 부담자와 강제 한도를 명시합니다. 자손 프로세스와 서비스 작업도 명시된
후원자나 서버 예산에 귀속합니다. 클라이언트가 무제한 작업을 떠넘겨 한도를 우회하면
안 됩니다. 외부 공개 전에 비용을 차감하고, 할당 실패를 정상 오류로 처리하며, 전역·복구
예약을 보존합니다. 종료 후에도 공유 자원에 비용 부담자가 남아야 하며, 다른 주체에게
재사용 페이지를 노출하기 전에 내용을 0으로 지웁니다.

생성·조회·이전·회수·닫기·파괴의 선형화 지점을 명시합니다. 회수는 권한 모델에 따라
위임된 별칭을 무효화하고, 새 사용을 막으며, 이미 수락한 작업의 종료 대기 또는 취소를
별도로 수행해야 합니다. 논리적 권한 회수와 물리적 자원 반환은 다릅니다. 한도가 있는
비동기 반환 프로토콜, 세대 번호 순환·슬롯 영구 폐기 규칙, 완료 토큰을 선택합니다.
참조, CPU 접근, 필요한 주소 변환 무효화가 모두 끝나기 전에는 해제하지 않습니다.
장치 페이지에는 F05의 DMA 조건도 추가합니다. 종료된 클라이언트 예산이 0이 된 후에도
정리 작업의 실행 예산은 유지되어야 합니다.

단계/시험: 1.1에서 소유권 원칙을 명시하고, 2단계 적대적 네이티브 시험 전에 원장·상태
기계를 확정합니다. 권한 이전·조회·종료·재사용을 경쟁시키고, 사용자 힙뿐 아니라 모든
메타데이터 풀을 소진시킵니다. 반복 주기 뒤 오래된 핸들, 주체 간 데이터 잔존, 원장을
확인합니다. SMP 활성화 전에는 CPU 간 주소 변환 무효화(shootdown)·확인 응답과 동시
재사용 시험을 추가합니다.

### F04 - 크기가 제한된 IPC만으로 시스템 호출과 생명주기가 정의되지 않음

근거: 영문 [DIRECTION.md](DIRECTION.md) 76행, [ROADMAP.md](ROADMAP.md) 27·48행.
잠금 상태에서 콜백을 금지하는 규칙은 유용하지만 대기, 우선순위 역전, 취소, 사용자
메모리 경쟁까지 해결하지는 않습니다.

실패 시나리오와 결과: 고우선순위 복구 클라이언트가 중간 우선순위 작업에 밀린
저우선순위 서버를 기다리거나, 호출자가 권한·길이 검사가 끝난 공유 요청을 수정하거나,
이미 확정된 쓰기를 시간 초과 후 재시도할 수 있습니다. 메시지 크기 한도는 이를 막지
못합니다.

수정: 작은 연산 표에 검증된 입출력 형태, 최대 커널 작업량, 오류, 대기·기한 동작,
취소 지점, 권한 이전 소유권, 상대 종료 시 효과를 명시합니다. 큐 포화와 부분 복사의
동작을 정의하되 권한의 부분 이전을 허용하지 않습니다. 인가와 효과 선택에는 하나의
변경 불가능한 요청 스냅샷을 사용합니다. 명확한 동시 변경 규칙 아래 데이터 버퍼를
고정하거나 접근을 중재합니다. 사용자 메모리 복사 결함은 통제되지 않는 커널 결함이
아니라 프로세스 오류가 되어야 합니다. 생성·시작·종료·강제 종료·대기와 재시작 세대,
대기자 및 미완료 응답 해제 방법을 정의합니다.

최초 구현에는 명시적인 요청 ID를 갖춘 제한된 비동기 요청·응답이 합리적인 작은
선택입니다. 동기 호출 연쇄를 선택한다면 순환·상대 종료를 포함한 제한된 우선순위·예산
양도 또는 증명 가능한 다른 역전 한도를 정의합니다. 복잡한 실시간 프레임워크를 기본으로
추가하지 않습니다. 대기나 무제한 회수 순회 중 코어·IRQ 임계 잠금을 유지하면 안 됩니다.
효과 확정 이후 취소는 명확한 완료·결과 불명 상태를 반환해야 하며, 임의의 효과를
되돌렸다고 주장해서는 안 됩니다.

네이티브 격리에는 CPU/ELF 프로파일도 필요합니다. 사용자 진입·복귀 상태, 페이지 권한,
특권 I/O 제한, 활성화한 모든 스레드별 아키텍처 상태의 보존을 선택합니다. FP/SIMD를
활성화하면 해당 상태도 포함됩니다. ring 3라는 이름만으로 시험 판정 기준이 되지 않습니다.

단계/시험: 1.1에서 최소 형태·버전·오류 규칙을 정합니다. 최초 구현 연산의 의미론을
2단계 적대적 실행 전에 완성합니다. 우선순위 역전, 중첩 대기, 상대 종료, 큐 포화,
결함이 나는 복사, 이중 응답, 늦은 취소, 동시 요청 변경, 서로 다른 레지스터·메모리
상태를 쓰는 네이티브 작업자 2개를 시험합니다. 미래 시스템 호출 전체를 동결하지 말고
버전 관리 가능성을 보존합니다.

### F05 - 사용자 모드 드라이버 이전에 장치 권한의 차단 우선 관문 필요

근거: 영문 [DIRECTION.md](DIRECTION.md) 81·185행, [ROADMAP.md](ROADMAP.md) 64·76행.
위험은 인식했지만 '지원되는 경우'는 승인 규칙이 아니며, 3단계 드라이버 권한 부여
이전에 명시적인 격리 관문이 없습니다.

실패 시나리오와 결과: 보호된 드라이버가 코어 메모리를 가리키는 설명자를 설정하거나,
죽은 뒤에도 DMA를 계속 실행하거나, 코어 타이머를 지연시키는 인터럽트 폭주를 일으킬
수 있습니다. 일회용 VM 안에서도 동일 코어 생존을 무너뜨립니다. 호스트 격리와 게스트
내부 격리는 서로 다른 주장입니다. VirtIO의 access-platform 기능과 실제 플랫폼 주소
변환을 검증해야 합니다. 해당 기능의 부재는 물리 주소 사용을 허용할 뿐, 제한된 게스트
DMA를 보장하지 않습니다.
[VirtIO 1.2, 6절](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)

수정: 요청자·도메인·MMIO·인터럽트를 모두 포함한 프로파일 하나를 검증하고, 선언된
위협 모델을 강제하지 못하면 원시 장치 접근을 거부합니다. 비신뢰 드라이버에게 IOMMU
테이블·라우팅·인터럽트 제어 권한을 주지 않습니다. 장치 프로토콜·재설정 정책은 격리된
모듈에 둡니다. 정확한 장치 기능 협상과 버스 마스터 활성화 순서를 고정합니다.
강제 가능한 격리가 없다면 CPU 전용 작업 또는 명확히 표시한 신뢰 드라이버 실험은
진행할 수 있지만, 적대적 드라이버 격리를 통과했다고 해서는 안 됩니다. 제한 없는
설명자·MMIO 작성자가 장치에 요청할 수 있는 접근 범위는 바운스 버퍼만으로 제한되지
않습니다.

회수 순서를 정의합니다. 새 제출과 MMIO 권한을 차단하고, 필요한 소스를 정지·마스킹하며,
DMA 매핑을 제거하고, 해당 무효화와 미완료 접근 장벽을 끝내고, 장치 재설정·정지 상태를
확인한 뒤 메모리를 재사용하거나 다시 연결합니다. 정확한 순서는 이 일반 목록이 아니라
선택한 전송 방식에 맞춰야 합니다. VirtIO 재설정 완료에는 장치 상태 확인 응답과 재설정
후 큐·알림 보장이 있습니다. 재설정 값을 쓰는 것만으로 관문을 통과하지 않습니다.
[VirtIO 1.2, 2.4절](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)

VT-d의 인터럽트 소스 검증·재매핑과 변환된 접근의 종료 대기는 별개의 기제입니다.
IOMMU 존재 플래그만으로 충분하다고 보지 말고, 선택한 프로파일이 실제로 구현하는
기제를 계약에 명시합니다.
[Intel VT-d, 5장](https://cdrdv2-public.intel.com/831418/vt-directed-io-spec.pdf),
[Intel VT-d, 주소 변환 무효화·접근 종료 정의](https://cdrdv2-public.intel.com/671081/vt-directed-io-spec.pdf)

시간 초과 시 장치와 안전한 재사용이 입증되지 않은 메모리를 고정 예약 범위 안에
격리합니다. 완전한 자원 반환이 아니라 기능 저하로 보고합니다. 소스별 인터럽트 작업량·
발생률 한도, 넘침·마스킹·재활성화 규칙, 드라이버 협조와 무관한 코어 소유 선점 타이머를
정의합니다. 실제 하드웨어의 명세 위반은 명시적으로 제외할 수 있지만, 정상 장치를
악의적으로 프로그래밍하는 일반 상황까지 제외하면 안 됩니다.

단계/시험: 1.1에서 필수 기능을 결정하되 최초 부팅부터 IOMMU 코드를 요구하지 않습니다.
3단계 장치 권한 부여 이전에 진입 관문을 추가합니다. 금지된 DMA·MMIO 접근, 인터럽트
폭주, 드라이버 종료 중 진행 중인 DMA, 실패한 재설정, 늦은 완료, 버퍼 재사용에도
코어와 관계없는 관찰 작업의 진행이 유지되어야 합니다. 실제 하드웨어는 별도의 후속
적격성 검증 대상입니다.

### F06 - 고정 이미지 신뢰와 온라인 최신성·오프라인 동작 분리

근거: 영문 [DIRECTION.md](DIRECTION.md) 36·108행,
[ROADMAP.md](ROADMAP.md) 49·65·74·123행.
3단계는 이미 취소되거나 재전송된 패키지 거부를 요구하지만 키 교체, 롤백, 관련 출시
기제는 6단계에 모여 있습니다. 시계·엔트로피 모듈은 이름만 있고 의존성·실패 정책이
정의되어 있지 않습니다.

실패 시나리오와 결과: 오프라인 장치가 오래된 인가를 최신으로 받아들이거나, 만료 때문에
모든 설치 앱과 복구를 비활성화할 수 있습니다. 유효한 옛 서명을 허용된 복구 롤백과
혼동할 수도 있습니다. 독립적인 기준점 없이 로컬 버전 카운터 전체를 옛 디스크 스냅샷으로
복원하면 롤백 방지 주장이 깨집니다.

수정: 2단계는 고정된 외부 신뢰 루트로 고정 이미지를 검증할 수 있습니다. 이것만으로
장치 내 키 생성이나 실제 시각 서비스가 필요한 것은 아닙니다. 코어 단조 시간 기한을
실제 시각의 신뢰 및 엔트로피 품질과 분리합니다. 3단계 TLS·등록 이전에 신뢰 시각·초기화
정책과 사용 불가·실패 상태가 있는 엔트로피 소스를 선택합니다. 키 생성과 보안 민감
세션이 시험용 시드나 잘못된 시각을 조용히 사용하지 못하게 합니다. 시험 키와 운영
권한은 명확히 구분합니다.

감사 가능한 업데이트 검증 설계를 사용하고, 정확한 서명 바이트 인코딩, 도메인·스키마
분리, 제한된 파싱을 정의합니다. TUF는 외부 경로로 확보한 루트 신뢰, 영속 버전,
시간 기반 최신성 검사의 1차 참고 자료입니다. 전체 구현을 코어에 넣으라는 요구는
아닙니다.
[TUF 명세 1.0.36, 5.1~5.6절](https://theupdateframework.github.io/specification/v1.0.36/)

제안하는 오프라인 계약: 이미 로컬에서 취소되지 않았다면 설치 산출물은 마지막으로
수락한 로컬 인가 아래 실행합니다. 최신성이 오래되었거나 불명이면 새 승인·권한 확대를
막되, 봉인된 복구 경로를 자동으로 잃게 하지는 않습니다. 오프라인 노드는 받지 못한
권한 취소를 알 수 없다는 한계를 명시합니다. 새 서명 메타데이터·이동식 매체가 로컬
지식을 갱신하는 방법을 정의합니다. 인가 세대·최소 보안 수준을 실행 내용의 버전과
분리합니다. 명시적으로 허용된 호환 가능한 옛 실행 내용으로 돌아가는 것과 옛 신뢰
메타데이터 재전송은 다릅니다. 적대적인 디스크 전체 롤백에 저항하려면 독립적인 최신성
기준점이 필요합니다. 아니면 초기 QEMU 위협 모델에서 이를 명시적으로 제외합니다.
개발을 시작하기 위해서만 TPM이 필요한 것은 아닙니다.

단계/시험: 2단계 승인 이전에 이미지 신뢰 루트를 고정합니다. 최소 신뢰 상태·롤백 규칙은
3단계로 앞당기고, 운영 키 교체 훈련과 시스템 A/B 출시 적격성 검증은 6단계에 둡니다.
시계 없음, 역행 시계, 엔트로피 불가, 메타데이터 만료, 알려진 권한 취소, 오프라인
재실행, 서명된 옛 실행 내용, 허가 없는 권한 변경, 신뢰 상태 저장 중단을 시험합니다.

### F07 - 활성화와 저장소의 충돌·동시성 프로토콜 정의

근거: 영문 [DIRECTION.md](DIRECTION.md) 99·114행,
[ROADMAP.md](ROADMAP.md) 64·74·124행.
현재 실행 연결(live binding)과 다음 부팅 선호 버전(preferred version)의 분리, 데이터
이행 경고는 옳습니다. 하지만 확정 지점과 충돌 이후 허용되는 상태가 아직 없습니다.

실패 시나리오와 결과: A가 쓰기·장치 권한을 보유한 채 B가 활성화되거나, 설치 중단으로
실행 내용·신뢰 데이터보다 선호 버전이 먼저 저장되거나, B가 비가역적으로 바꾼 스키마에
A로 롤백할 수 있습니다. 개별 서명이 모두 유효하고 메모리 포인터 변경이 원자적으로
보이더라도 데이터가 손상될 수 있습니다.

수정: 연산 세대와 문서화한 하나의 선형화 지점을 갖춘 작은 생명주기를 정의합니다.
변경 불가능한 후보 준비, 검증·준비, 이전 요청 차단, 종료 대기·취소, 호환 상태 이전,
연결 전환, 정상성 확인, 별도의 다음 부팅 선호 버전 확정을 구분합니다. 충돌 후 사용
불가·결과 불명 반환을 포함해 각 전환 경계에서 요청에 생기는 일을 정의합니다.
외부 효과의 정확히 한 번 실행을 약속하지 않습니다. 재시작 후 인가되고, 완전히 존재하며,
상태와 호환되는 버전을 선택할 수 있도록 충분한 의도·확정 상태를 영속 기록합니다.
과거에 정상적이었다는 이유로 취소된 산출물을 되살려서는 안 됩니다.

최초 쓰기 가능 서비스의 데이터 이행 정책은 호환 스키마 또는 명시적인 백업·복원으로
제한합니다. 파괴적인 이행을 거부해도 됩니다. 파일 flush, rename, 선호 버전 확정에서
영속 완료 응답이 뜻하는 바를 정의합니다. 선택한 블록 장치의 순서·캐시 가정과 쓰기
손실·순서 뒤바뀜·부분 기록의 결함 모델을 명시합니다. QEMU 재부팅만으로 정의된 전원
손실 시험을 대신할 수 없습니다. 복구는 고장 난 후보에 의존하지 않고 마지막 유효 상태
또는 명확한 실패를 노출할 수 있어야 합니다.

단계/시험: 6단계 시스템 업그레이드까지 미루지 말고, 3단계 사용자 데이터 또는 장치·
서비스 전환 전에 해결합니다. 동시 읽기·쓰기를 유지하면서 모든 영속 저장·활성화
경계에 중단을 주입합니다. 호스트가 보유한 예상 데이터 원장과 허용 상태 모델로
판정합니다. 명세에 따른 이전 상태 또는 확정된 새 상태여야 하며, 영속 완료 응답을
마친 데이터의 누락, 미인가 코드, 호환되지 않는 혼합 상태는 허용하지 않습니다.
시스템 이미지 A/B 구현은 6단계에 남겨도 됩니다.

### F08 - 생존 관문에는 독립 판정 기준과 사전에 정한 예산이 필요

근거: 영문 [DIRECTION.md](DIRECTION.md) 87행, [REQUIREMENTS.md](REQUIREMENTS.md) 44행,
[ROADMAP.md](ROADMAP.md) 35·54·89·100행.
프로세스 수와 8시간 연속 시험은 구체적이지만, '진행', '한도가 있음', '정상성',
'지연 측정'에는 여전히 서로 양립하지 않는 합격 기준이 들어갈 수 있습니다.

실패 시나리오와 결과: 공격자가 관찰용 로그를 출력하거나, 시험 도구가 시험 대상의
자체 카운터를 믿거나, 멈춘 게스트 시계가 영원히 시간 초과에 도달하지 않거나, 느린
단조 누수가 짧은 시연을 통과할 수 있습니다. 생성기가 시험 코드를 수정하지 못하더라도,
판정 기준이 후보의 자체 성공 보고를 믿는다면 충분하지 않습니다.

수정: 1.1에서 시험 도구와 판정 기준(oracle)의 신뢰 경계를 정의합니다. 실제 운영
경로를 통해 서로 다른 주체와 복구 경로에 외부 시간 제한이 있는 검증 요청을 보냅니다.
응답의 출처는 자유 형식 공용 로그가 아니라 보호된 채널로 식별합니다. 결과를 소스·
이미지·시험·프로파일 해시에 연결하고, 재설정·부팅 사건을 외부에서 기록합니다.
스케줄러 틱만 보지 말고 유용한 작업의 완료와 오류를 관찰합니다. 게스트 단조 시간 측정과
호스트 단조 시간 기한을 함께 유지합니다. 시험 코드·입력 자료·결과 서명 권한에 생성기·
후보의 쓰기 접근을 허용하지 않습니다. 진행 없음, 재설정, 손상, 승인 실패를 판정기가
거부하는지 보이도록 의도적으로 고장 낸 실패 대조군(negative control)을 추가합니다.
이는 판정기를 확인하는 것이지 모든 구현 결함의 부재를 입증하는 것은 아닙니다.

각 관문 전에 정확한 승인 한도, 최대 지연, 반복 횟수, 자원 기준선, 허용하는 고정 캐시
여유량이 포함된 합격 기준표를 공개합니다. 아래 값은 검토자가 제안한 보정 시작값이며,

때는 합격 시험 전에 근거를 기록합니다. 실패를 본 뒤 통과로 바꿔 부르려고 수정하면

6단계에 둡니다.

### F09 - 권한은 모델의 문구가 아니라 신원·객체 버전에 결합되어야 함

근거: 영문 [DIRECTION.md](DIRECTION.md) 121·170행,
[ROADMAP.md](ROADMAP.md) 49·72·98행.
정책 경계는 올바르지만, 앞선 터미널·감독자·승인 기능에도 필요한 정확한 명령·타입 있는
동작 기반이 AI와 함께 5단계에 배치되어 있습니다. 승인과 실제 효과 사이의 신원·버전
결합도 빠져 있습니다.

실패 시나리오와 결과: 사용자가 특정 파일·모듈 수정 계획을 승인했지만 실행 전 경로명·
연결 대상이 바뀔 수 있습니다. 저장된 작업 흐름이나 의미 요약이 나중에 승인을 묵시적
권한으로 재사용하거나, 원본 ACL이 바뀐 뒤에도 예전 인가 질의가 실행될 수 있습니다.
타입이 있는 JSON만으로 이런 인가 경쟁이 해결되지 않습니다.

수정: 2단계 터미널과 3단계 모듈 관리자에 필요한 결정적 로컬 명령·동작 부분집합만
먼저 구현합니다. 5단계는 의도 계획을 추가하는 것이지 두 번째 권한 기제를 만드는 것이
아닙니다. 각 효과를 인증된 주체, capability, 안정된 객체 식별자·세대, 연산 인수,
정책 세대, 승인 범위, 기한, 요청·트랜잭션 ID에 결합합니다. 효과 확정 경계에서 검증하거나
승인 조건을 보존하는 예약을 사용합니다. 알 수 없는 연산과 변경된 선행 조건은 실패하거나
새 인가를 요구합니다.

모델, 검색된 텍스트, 캐시된 작업 흐름, 서명된 패키지는 입력이지 사용자 승인 주체나
서명 주체가 아닙니다. 승인 서비스는 신뢰할 수 있는 사용자 경로로 확인을 받고, 모델의
안심시키는 문장이 아니라 검증된 필드로 표시 효과를 구성해야 합니다. 의미 캐시 적중
시에도 현재 원본 권한을 재검사합니다. 원문 콘텐츠·모델 업로드 허가는 별도로 유지합니다.
취소·재시도는 F04/F07을 따라 외부 효과를 조용히 중복 실행하지 않게 합니다.

단계/시험: 2단계 터미널 합격 전에 로컬 기반을 마련하고, 5단계 외부 효과 전에 전체
계약·주입 시험을 완료합니다. 승인 후 객체 교체, 특권·ACL 취소, 서비스 재시작,
위조 확인, 캐시 계획 재전송, 콘텐츠와 도구 결과의 프롬프트 주입을 시험합니다.
음성·의미 인덱싱·모델 통합까지 1단계로 앞당긴다는 뜻은 아닙니다.

### F10 - 미래 시스템 전체가 아니라 실험을 마친 좁은 계약을 동결

근거: 영문 [REQUIREMENTS.md](REQUIREMENTS.md) 8행, [DIRECTION.md](DIRECTION.md) 108행,
[ROADMAP.md](ROADMAP.md) 20·26·47행.
요구사항은 각 단계에서 세부 사항을 성숙시키도록 허용하지만, 1.1단계는 네이티브·런타임·
장치 실험 전에 manifest 동결을 요구합니다. 2단계는 최초 프로세스·복구·Wasm·SMP를
단일 관문으로 묶었습니다.

실패 시나리오와 결과: 추측한 의존성·상태·장치 필드가 v0에 고정되거나, Wasm 런타임의
플랫폼 요구 때문에 예정에 없던 커널 서비스가 생길 수 있습니다. 반대로 유용한 단일
코어 서비스 작업 전체가 무관한 SMP 작업을 기다리면, 실제 중간 진척을 정직하게 보고하기
어려워집니다.

수정: 1.1에서는 부팅 이미지 외형 계약과 초기 크기 제한 메시지 시험 자료만 동결합니다.
네이티브 ABI와 발전 중인 모듈 manifest는 실험 상태로 표시하고 버전을 부여합니다.
알 수 없는 권한 관련 필드는 거부합니다. 대표적인 성공·실패 경로 왕복 시험 이후 작은
운영 부분집합을 동결합니다. 포괄적인 IDL, 호환 계층, 범용 데이터 이행은 이 선행 조건에
포함하지 않습니다. 임의 런타임의 기본 기능을 맞추려고 코어 경계를 완화하지 않습니다.

네이티브 프로세스·중개기 격리 뒤에 버전을 고정한 Wasm 작업자 프로파일 하나를 검증합니다.
Wasmtime은 모듈 후보이지 필수 커널 의존성이 아닙니다. 공식 문서는 제한된 `no_std`
기능과 사용자 정의 플랫폼 연결 지점을 설명하며, 네이티브 컴파일·기능은 별도 검토가
필요합니다. 데스크톱 기본 구성이 이식될 것이라 가정하지 말고 선택한 정확한 버전을
확인합니다. 감사 가능한 인터프리터나 외부에서 빌드한 AOT 프로파일도 OpenRhiza 아래에
다른 OS를 추가하지 않고 고려할 수 있습니다.
[Wasmtime 플랫폼 지원](https://docs.wasmtime.dev/stability-platform-support.html)

단계 수정: 2단계를 단일 코어 네이티브 격리, 고정 복구·Wasm 작업자 적격성 검증,
SMP 하위 관문으로 명시적으로 나눕니다. 앞의 두 관문을 통과하면 명시적인 단일 vCPU
프로파일로 후속 작업을 허용합니다. SMP 활성화·지원 주장에는 별도의 동시성·TLB·인터럽트
시험이 필요합니다. 이는 기존 6개 순차 단계 표현에 대한 수정 제안이며, 주 작업에서
반영하기 전에 이를 우회해도 된다는 허가가 아닙니다. 후속 제품 목표는 모두 보존하되,
전체 구현을 최초 부팅 조건으로 삼지 않습니다.

## 최소 단계 수정안

## 타당한 부분

- 재시작 경계가 분명하고, 이식 가능한 감사된 의존성을 허용하며, 다른 OS에 게스트 런타임을 의존하지 않습니다. 기존 산출물·성공 횟수를 새 증거로 승격할 수 없습니다. 영문 [README.md](../README.md) 17행.
- Wasm 아래의 하드웨어 프로세스 격리, 작은 기제 코어, 부팅·빌드·특권 모듈을 명시적으로 포함한 TCB는 적절한 시작 경계입니다. 이번 발견 사항을 해결하기 위해 Linux/BSD/Windows/Android 런타임으로 다시 작성할 필요는 없습니다. 영문 [DIRECTION.md](DIRECTION.md) 45·65행.
- 복구 정책을 코어 밖에 두고, 부팅이 바뀌지 않은 생존 증거를 요구하며, watchdog 재설정을 격리 성공으로 보지 않는 구별은 유지해야 합니다. 영문 [DIRECTION.md](DIRECTION.md) 87행.
- 오프라인 설치 동작, 분리된 빌드·시험·서명·승인 책임, 서명을 정확성이 아니라 신원 증거로 취급하는 원칙은 큰 신뢰 우회를 막습니다. 영문 [DIRECTION.md](DIRECTION.md) 36행, [REQUIREMENTS.md](REQUIREMENTS.md) 49행.
- 명령 우선 상호작용, 한국어·영어 IME, 실제 앱·프로세스·창 상태, 백그라운드 예산, 내려받아 플레이하는 게임이 동작 목표로 보존되어 있습니다. 의미 지식은 비공개이며 재구축 가능한 보조 계층이고, 새 파일 시스템 형식을 강제하지 않습니다. 영문 [DIRECTION.md](DIRECTION.md) 119·168행.
- 하나의 고정 QEMU 프로파일, 후속 실제 하드웨어 검증, 연기된 플랫폼·자체 호스팅·호환 계획은 초기 범위를 합리적으로 제한합니다. 위 수정은 최초 부팅 전에 전체 시스템 형식 검증, 모든 하드웨어 지원, 공개 Nexus를 요구하지 않습니다. 영문 [ROADMAP.md](ROADMAP.md) 137행.

### 주요 일관성 확인

- **초기 콘솔:** 일관됨. K에서 DMA를 쓰지 않는 폴링 UART의 좁은 권한 또는 동등하게 제한된 전송 방식을 선택하고, N에서 권한 감사·거부 시험을 요구합니다. 일반 장치는 계속 D의 대상입니다. DMA가 없다는 사실만을 격리 증거로 보지 않으면서 복구가 미래 범용 드라이버에 의존하는 문제를 피합니다. 영문 [IMPLEMENTATION_GATES.md](IMPLEMENTATION_GATES.md) 27·111행, [DIRECTION.md](DIRECTION.md) 118행.
- **외부 등록·설치:** 일관됨. 3.2단계 프로토콜·신뢰 정책 개발이 외부 등록·설치를 허가하지는 않습니다. 3.3에서 최소 신뢰 영속성·복구가 검증될 때까지 명시적으로 보류합니다. 네트워크 개발은 영속적이고 인증된 노드 신원의 증거가 아닙니다. 영문 [ROADMAP.md](ROADMAP.md) 98·115행, [ASTRA_REVIEW_DISPOSITION.md](ASTRA_REVIEW_DISPOSITION.md) 60행.
- **단일 vCPU/Wasm/SMP:** 일관됨. N 뒤에 W가 오며, 둘 다 통과한 후 검증된 단일 vCPU 프로파일로 진행할 수 있습니다. 독립적인 2-vCPU 관문을 통과하기 전 SMP는 비활성 상태이며 지원을 주장하지 않습니다. N만 통과하거나 W 요구사항을 문서화한 것만으로 2단계 단일 vCPU 프로파일이 완료되지는 않습니다. 영문 [ROADMAP.md](ROADMAP.md) 65행, [IMPLEMENTATION_GATES.md](IMPLEMENTATION_GATES.md) 92행.

### 진행을 막지 않는 수정 사항과 남은 K 작업

**P2 문구 차이이며 K 계약 작업의 차단 요소는 아님:**
영문 [IMPLEMENTATION_GATES.md](IMPLEMENTATION_GATES.md) 199행은 자원 반환 기한을
'해제 완료 확인(acknowledged teardown)'부터 측정하지만, 영문
[ASTRA_PLAN_REVIEW.md](ASTRA_PLAN_REVIEW.md) 390행의 최초 F08 후보는 중지·회수
요청이 수락되는 시점부터 측정합니다. 확인 응답을 최종 해제 완료로 해석하면 측정 구간이
시작되기 전에 해제가 무한히 오래 걸려도 숨길 수 있습니다. N 합격 기준표를 동결하기
전에 '중지·회수 요청이 수락된 후'로 복원하고, 수락 사건과 그 요청 지연 한도를
정의합니다. 수치 후보는 여전히 프로파일 보정 대상이며, 이 문구 수정으로 지금 측정된
한도를 주장해서는 안 됩니다.

실제 K 작업에는 고정된 단일 vCPU 도구 모음·펌웨어·머신·장치 프로파일 및 격리된
실행 명령, 부팅 신뢰·파서·메모리 인계 ADR과 시험 자료, 최초 주체 권한과 상주 복구·
콘솔 권한, 초기 소유권·ABI 형태와 장치 거부, 독립 시험 도구 채널·부팅 및 재설정
관찰·초기 기한의 선택과 검토가 여전히 필요합니다. 이 구체적인 선택과 시험 자료는
1.2단계 전에 진입 검토를 받아야 합니다. 후속 런타임 강제와 적대적 시험은 명시한 각
관문에 남아 있으며, 이번 계획 수준 승인에 몰래 추가한 선행 조건이 아닙니다.
영문 [IMPLEMENTATION_GATES.md](IMPLEMENTATION_GATES.md) 10·45행,
[ROADMAP.md](ROADMAP.md) 46행.
