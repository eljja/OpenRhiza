# 구현 착수·수락시험 통과 기준

[영문 원문](IMPLEMENTATION_GATES.md) · [한국어 목차](../README.ko.md)

상태: 2026-10-03 Astra 지적 F01~F10을 반영한 계획 요구사항. 아직 통과하지 않았습니다.
제품·아키텍처는 [방향](DIRECTION.ko.md), 순서는 [로드맵](ROADMAP.ko.md)이 정합니다.
이 문서는 각 경계에서 필요한 결정과 근거를 정의하며 별도 로드맵이 아닙니다.

## K: 첫 커널 구현 전 (1.1단계)

다음을 포함하는 소수의 검토된 ADR과 범위가 제한된 시험 자료를 기록합니다.

- 정확한 호스트 도구체인, 펌웨어·로더, QEMU 머신·CPU·장치, 메모리·단일 vCPU 구성,
  상위 Cargo/rustup 설정과 빌드 분리, 의존성·라이선스 고정, 재현 가능한 실행 방법.
- 부트 신뢰 기반(TCB)과 신뢰 방식: 어느 구성요소가 어떤 바이트를 검증하고 어떤 외부 신뢰 기준을 사용하는지.
  초기 모듈 허가 전에 코드와 권한·설정을 함께 인증합니다. 진단 부팅에는 호스트를 신뢰하는 개발 이미지를 쓸 수 있으나
  검증 부팅·물리 공격자에 대한 보장 제외를 명시합니다. 펌웨어 설치만으로 진위가 보장되지는 않습니다.
- 버전과 길이 제한을 가진 진입 형식, 영역·중첩 검사, 진입 CPU·스택·페이지 테이블 상태, 펌웨어 종료 규칙,
  소유·예약 프레임, 불변 상주 초기 이미지 기술 정보, 파서 소유권.
  UEFI를 선택하면 메모리 맵·ExitBootServices와 종료 후 콘솔 소유권을 검증합니다.
  나중에 비신뢰 ELF를 파싱하면서 코어 TCB를 조용히 넓히지 않습니다.
- 첫 사용자 권한 주체, 초기 최대 권한, 보호된 코어·복구 예약 자원. 일반·위임 권한으로 이를 제거할 수 없습니다.
- 입력·출력, 재실행 조건, 재시작 한도·대기 간격, 자원 소진·기능 저하 상태를 포함한 상주 복구 의존성 그래프.
  초기 콘솔은 변경 가능한 저장소·모델·네트워크·GUI·정상 감독자에 의존하지 않습니다.
  좁은 비-DMA 폴링 UART 권한 또는 동등하게 제한된 전송 경로를 쓰는 격리 직렬 모듈을 선정·검토합니다.
- 자원 소유권·사용량 계산 원칙, 버전·오류·메시지 형식 초안, 선택한 네이티브 진입·복귀와 활성 아키텍처 상태,
  장치 권한의 기본 거부 규칙. 완전한 시스템 호출·스케줄러·회수 계약은 적대적 시험 전 N에서 확정합니다.
- 독립 시험 도구의 소유권, 외부에서 관찰한 부팅·리셋 식별자, 인증·귀속 가능한 시험 채널,
  호스트 단조 시계 기한, 초기 3회 부팅·패닉 진단 사례. 게스트 로그 문구에만 의존하지 않습니다.

검토한 부트 이미지 형식과 초기 시험 자료를 확정하되, 네이티브 ABI와 더 넓은 모듈 매니페스트는
버전이 있는 실험 상태로 둡니다. 모르는 권한 필드는 거부합니다.
각 동작 부분집합은 대표적인 정상·비정상 왕복을 시험한 뒤, 이를 사용하는 구성요소를 허용하기 전에 확정합니다.

K에 완전한 파일시스템, 동적 레지스트리, IOMMU 구현, Wasm 런타임, SMP, 데스크톱, AI, 운영 릴리스는 필요하지 않습니다.
구체적 선택과 진입 근거는 아직 없으며, 이 목록 자체는 K 통과 근거가 아닙니다.

## N: 적대적 CPU 전용 실행 (2.1단계)

적대적 CPU 전용 시험 모듈을 허용하기 전에 검토한 부분집합을 구현하고 정확한 연산·자원 계약을 정의합니다.

- 페이지, 페이지 테이블, 스택, 프로세스·스레드 슬롯, 핸들, 큐의 바이트·권한, 공유·고정 버퍼,
  장애·로그 기록, 정리 작업을 사용량에 포함합니다. 비용 부담 주체, 위임·서비스 작업의 지원 주체와 각 상한을 명시합니다.
  객체 공개 전에 차감하고, 종료 후에도 공유 자원 소유자를 유지합니다. 실패한 요청이 일부 비용·권한을 남기지 않게 하며,
  재사용할 비공개 페이지는 0으로 지웁니다.
- 생성·조회·이전·철회·닫기·파괴의 선형화 시점, 별칭 철회, 슬롯 세대 소진·폐기, 정리 예산·완료 토큰을 정합니다.
  논리적 철회는 새 사용을 막습니다. 회수에는 허가된 작업 종료·취소와 필요한 CPU 주소 변환 무효화 완료도 필요합니다.
  실패한 주체의 예산이 소진되어도 정리는 제한된 작업량과 별도 예산을 유지합니다.
- 시스템 호출마다 작업량 한도, 불변 요청 스냅샷, 검사, 사용자 메모리 복사 오류, 큐 가득 참·오류·부분 출력,
  권한 이전, 대기·기한·취소, 상대 종료의 효과를 정합니다. 공유 데이터 버퍼에는 동시 변경·메모리 고정 규칙이 필요합니다.
- 요청 ID가 있는 작은 비동기 요청·응답 계약을 우선합니다. 동기 의존성은 순환·종료를 포함해
  우선순위·예산 역전 상한을 입증해야 합니다. 무제한 순회나 대기 중 코어·IRQ 임계 잠금을 잡지 않습니다.
  확정 뒤 시간 초과는 완료 또는 결과 불명으로 보고하며, 효과가 취소됐다고 간주하거나 중복 재시도를 허가하지 않습니다.
- spawn/start/exit/kill/wait, 재시작 세대, 미완료 응답·대기자 정리를 정합니다.
  사용자 진입·복귀, W^X, 특권 I/O 거부, 장애 처리, 활성 FP/SIMD를 포함한 스레드별 아키텍처 상태를 확인합니다.
- 복구용 CPU·프레임·객체/큐 슬롯·진단 예약을 강제합니다. 일반 감독자·로거·콘솔을 고장 내고 일반 자원을 포화시켜
  복구와 무관한 유용한 작업을 시험합니다. 종속 클라이언트는 제한 시간 안에 서비스 오류를 받을 수 있지만,
  일반 장애가 복구의 최소 권한을 철회할 수는 없습니다.
- K 신뢰 기준에 따라 고정 초기 이미지를 허가합니다. LLM과 독립적으로 터미널·감독자를 위한 작은 타입 명령·작업 레지스트리를 제공합니다.
  일반 감독자 충돌은 장애 모델에 포함하고, 명시된 권한·키 정책 TCB의 침해는 별도 가정으로 둡니다.

N 통과 선언 전에 수치 한도를 공개하고 아래 독립 판정기로 실제 운영 경로의 장애·경쟁·포화·오래된 핸들·메타데이터 풀·회수 시험을 통과합니다.
장치는 별도로 검토한 초기 콘솔 계약으로 제한합니다. N이 미검증 직접 DMA/MMIO/IRQ 권한을 허용하지는 않습니다.

## W와 SMP: 런타임 검증 (2.2·2.3단계)

N 이후 격리된 Wasm 작업자·중개기 환경 하나의 버전을 고정하고 검증합니다.
인터프리터 또는 AOT/JIT 기능, 플랫폼 연결점, 호스트 호출 계약을 명시적으로 선택합니다.
데스크톱 런타임 기본값이나 전체 WASI가 이식 가능하다고 가정하지 않습니다.
작업자·중개기 충돌, 무한 루프, 잘못된 호스트 요청에도 N이 유지되어야 합니다.

초기 단일 vCPU 환경은 N·W 이후 진행할 수 있습니다. SMP는 두 vCPU 조건에서 동시 소유권,
TLB 무효화·확인, 인터럽트, 회수·재사용, 아키텍처 상태를 통과할 때까지 미완료로 보고합니다.
그 뒤에만 SMP를 활성화·주장합니다. 검증한 환경의 6단계 순서를 유지하되 미검증 SMP를 모든 결과에 암묵적으로 포함하지 않습니다.

## D: 일반 장치 권한 부여 전 (3.1단계)

드라이버에 직접 장치 권한을 주기 전에 정확한 요청자·도메인·MMIO·인터럽트 구성을 검증합니다.
필요한 DMA 주소 변환·access-platform 협상, 버스 마스터 활성화 순서, IRQ 출처 격리,
마스킹, 발생률·작업량 상한, 코어 소유 선점 타이머를 강제합니다.
주소 변환 테이블과 인터럽트 제어 권한은 비신뢰 드라이버에 주지 않습니다.

K에서 선택한 고정 비-DMA 콘솔은 일반 드라이버 순서의 좁은 예외이며 N에서 자체 권한 검토·거부 시험을 수행합니다.
다른 I/O 포트나 장치 레지스터를 노출하는 허가가 아닙니다.
강제 가능한 일반 장치 구성이 없으면 CPU 전용 작업을 계속하거나 신뢰 드라이버 실험으로 명시합니다.
적대적 드라이버 격리는 통과할 수 없습니다. QEMU가 호스트를 보호하는 것과 게스트 커널 보호는 별개입니다.

전송 방식에 맞는 철회 순서를 정합니다. 신규 제출·MMIO를 차단하고, 발생원을 제어하고, 매핑을 제거하고,
필요한 무효화·접근 완료 장벽을 수행하고, 리셋·정지를 확인한 뒤 메모리를 재사용하거나 다시 연결합니다.
리셋 값을 썼다는 사실만이 아니라 실제 완료 응답을 시험합니다.
기한을 넘기면 장치와 안전성이 확인되지 않은 페이지를 고정 예산 안에 격리하고 완전 회수로 보고하지 않습니다.
장치 프로토콜·리셋 정책은 모듈에 두고 코어는 제한된 권한을 강제합니다.

금지 DMA/MMIO, 인터럽트 폭주, I/O 중 드라이버 종료, 리셋 실패, 늦은 완료, 버퍼 재사용을 주입합니다.
하드웨어 규격 위반은 명시적 제외이며, 허용된 규격 준수 장치의 악의적 프로그래밍은 시험 범위입니다.

## A: 네트워크 허가·저장소·전환 (3.2~3.3단계)

TLS·등록·외부 패키지 허가 전에 신뢰할 실제 시각 초기화와 엔트로피 출처·실패 상태를 정합니다.
스케줄링용 단조 시간과 구분합니다. 시간·엔트로피가 잘못되거나 없을 때 보안 세션이나
시험 시드로의 키 생성을 조용히 허용하면 안 됩니다.

검토된 업데이트 검증 설계, 외부 신뢰 기준, 서명 바이트·스키마 인코딩, 제한된 파서,
영속 권한·보안 세대를 선택합니다. 설치 산출물은 로컬에서 철회되지 않았다면 마지막 수락 권한으로 실행합니다.
최신성이 불명확하거나 오래되면 신규 허가·권한 확대를 거부하면서 고정 복구와 승인된 설치 기능을 유지합니다.
오프라인 노드는 받지 못한 철회를 알 수 없습니다. 서명 메타데이터·이동식 매체 갱신,
승인된 옛 코드 버전 롤백, 복구 신뢰를 옛 허가 재전송과 구분합니다.
악의적 디스크 롤백의 완전한 방지에는 독립 최신성 기준점 또는 초기 환경의 명시적 제외가 필요합니다.

수명주기·영속 상태에는 요청 세대와 확정 시점을 정의합니다.
불변 후보 준비, 검사·준비, 기존 신규 작업 차단, 진행 작업 종료·취소, 호환 상태 이동,
활성 연결 전환, 상태 확인, 별도의 다음 부팅 선호 상태 저장 순서입니다.
중단 지점마다 허용 결과를 정하고 동시에 두 쓰기 주체가 존재하지 않게 합니다.
롤백 중 철회 산출물을 되살리지 않습니다. 초기에는 호환 스키마 또는 명시적 백업·복원만 허용하고
지원하지 않는 파괴적 이전은 거부합니다. 나중에 정상 상태가 됐다고 이미 영속 완료 응답한 데이터의 손실 근거를 지울 수 없습니다.

파일 flush·이름 변경·선호 상태의 영속 완료 응답, 블록·캐시 순서 가정, 쓰기 유실·순서 변경·부분 기록 장애 모델을 정합니다.
사용자 데이터나 실제 전환 전에 동시 클라이언트를 유지하며 모든 전이에 중단을 주입하고
호스트가 가진 예상 데이터·허용 상태 원장과 비교합니다. QEMU 재부팅만으로 전원 손실 시험이 되지 않습니다.
최소 신뢰 상태 복구는 여기서 갖추고 운영 키 교체 훈련·시스템 이미지 A/B 인증은 6단계에 둡니다.

## Intent: AI 작업의 효과 (5단계)

기존 로컬 타입 작업에 모델 계획을 추가합니다. 효과를 인증된 주체, 객체 권한, 안정적 객체·세대,
인자, 정책 세대, 승인 범위, 기한, 트랜잭션 ID에 연결합니다.
확정 시 다시 검사하거나 예약으로 승인 조건을 유지합니다.
신뢰된 사용자 확인 경로가 검증된 필드에서 효과를 표시하고 확인을 전달합니다.
모델 텍스트, 서명 패키지, 캐시 워크플로가 이를 사칭할 수 없습니다.

객체 교체, ACL·권한 철회, 재시작, 재전송, 확인 위조, 문서·도구 결과 주입을 시험합니다.
의미 캐시 결과는 현재 원문 권한을 다시 검사하고 콘텐츠 업로드는 별도 허가합니다.
외부 효과에는 N/A의 취소·재시도 의미를 적용합니다.
음성·개인정보, 게임 시간·오디오, UI 응답 한도는 각 환경의 시험 전에 확정합니다.

## 수락시험표와 독립 판정기

각 조건은 소스·이미지·시험·환경 해시, 권한 가정, 정확한 한도·임계값, 작업 부하·입력,
반복 수, 결과·오류 관찰, 고정 캐시·격리 허용량을 포함한 자원 기준치를 기록합니다.
시험·자료·결과 서명 키는 후보·생성자의 쓰기 권한 밖에 둡니다.
외부 확인 요청의 유용한 작업 결과를 보호된 주체·채널에 귀속시키고, 부팅·리셋을 외부 기록하며,
게스트·호스트 단조 시계 기한을 함께 사용합니다.
진행 중단·리셋·손상·잘못된 허가에서 반드시 실패하는 고장 대조군을 포함합니다.
공유 게스트 성공 로그만으로 통과하지 않습니다.

다음은 Astra가 제안한 초기 보정 후보이며, 실측 결과나 이미 확정된 요구가 아닙니다.
지정 환경에서 검증하고, 실패를 보존하면서 수락시험 전에 변경과 이유를 기록합니다.

| 경계 | 초기 보정 후보 |
| --- | --- |
| 1.3단계 | 새 이미지로 3회 부팅, 매회 호스트 <= 30 s; 예상 패닉은 별도 사례 |
| N 스케줄링 | 게스트 실행 시간 조각 <= 10 ms; 무관한 유용한 작업 사이 간격 <= 100 ms |
| N 명령 | 정상 복구 명령 응답이 게스트 <= 250 ms, 호스트 <= 5 s |
| N 복구 재실행 | 감독자 장애 주입 뒤 정상 예약 명령 경로가 게스트 <= 2 s, 호스트 <= 10 s 안에 복구 |
| N 자원 회수 | stop/revoke 요청 수락 뒤 게스트 <= 1 s, 호스트 <= 5 s 안에 원장 기준치+고정 허용량 도달; 생성·장애·철회 1,000회 |
| N 허가 | 각 한도 L에서 정한 결합 자원 범위 내 L은 허용, L+1은 부분 자원·권한 공개 없이 거부 |

자원 회수에서 수락은 보호된 연산의 선형화 시점입니다. 비동기 해제 전에 승인된 stop/revoke 요청을
기록하고 정리 책임을 확정하는 순간입니다. 최종 해제 완료 응답이 이 시점이 아닙니다.
외부 요청 제출, 보호된 수락, 관찰한 원장 기준치 도달을 따로 기록합니다.
수락시험표에는 제출부터 수락까지의 최대 지연과 호스트 전체 시간 제한도 수치로 정합니다.
늦은 수락으로 무제한 해제나 멈춘 요청 경로를 숨길 수 없습니다.

D에는 자체 IRQ·정지 기한과 격리 자원 상한이 필요합니다. A에는 허용 충돌 상태 목록과 영속 데이터 검사가 필요합니다.
데스크톱·음성·게임은 장시간 시험 전에 입력·렌더링 지연, 오디오 버퍼 부족, 메모리 증가,
게임 시간 오차의 허용치를 정합니다. 기반 환경의 시간 초과로 시험을 무효화할 수 있지만,
관찰 누락을 통과로 바꾸거나 외부 기한을 없앨 수는 없습니다.
경계 퍼징·실패 시험은 N/D/A에서 시작하고 6단계에서 장기 검증을 추가합니다.
