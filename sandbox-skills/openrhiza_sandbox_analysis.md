# OpenRhiza: Sandbox-Skills 현황 요약 및 발전 방향 분석

## 1. 현재 `sandbox-skills` 디렉토리 진행 상황 요약
현재 `sandbox-skills` 폴더에는 OpenRhiza OS 위에서 구동되는 독립적인 WebAssembly(Wasm) 기반의 "스킬(Skill)" 모듈들이 개발되고 있습니다. 모든 모듈은 Rust의 `#![no_std]` 환경에서 작성되었으며, 메모리 할당 최소화를 위한 커스텀 Bump Allocator와 호스트 OS 통신을 위한 FFI 인터페이스(`os_gui_*`, `os_log` 등)를 공유하고 있습니다.

주요 모듈은 다음과 같습니다:
*   **`rhiza_compiler_seed`**: 자체적인 마이크로 Rust 컴파일러로, 렉서, 추상 구문 트리(AST) 분석 및 메모리/포인터 연산이 포함된 Wasm 바이트코드(v6.0)를 직접 생성합니다. 내장된 Zero-Allocation VDOM 파서를 통해 컴파일 상태를 시각화합니다.
*   **`vfs_explorer_seed`**: AI 에이전트가 코드를 읽고 쓸 수 있는 3-Pane 구조의 IDE 환경입니다. 정적 가상 파일 시스템(VFS) 상태를 유지하며, 에이전트가 파일 수정 및 디렉토리 탐색을 할 수 있도록 간단한 JS 평가(`agent_eval_js`) 인터페이스를 제공합니다.
*   **`system_monitor_seed`**: 멀티 코어, 다중 GPU, LAN 등 하드웨어 토폴로지를 시각화하고 프로세스 상태를 관리하는 시스템 모니터입니다. 로그 추적 및 특정 프로세스(Rogue AI 등) 킬(Kill), 메모리 회수 등의 기능을 에이전트 API로 제공합니다.

## 2. 비판적 분석 (부족한 부분 및 한계점)
현재 구현된 코드들은 흥미로운 아키텍처를 제시하지만, 실제 시스템이라기보다는 "시뮬레이션" 또는 "프로토타입"에 머물러 있는 한계가 있습니다.

1.  **하드코딩된 모의(Mock) 데이터와 한계성**:
    *   VFS 파일 시스템 내용과 하드웨어 토폴로지(64코어, RTX 4090 등), 프로세스 목록이 모두 `static` 배열에 하드코딩되어 있습니다. 실제 호스트 환경의 하드웨어 정보를 반영하거나 실제 디스크 I/O를 수행하지 않습니다.
    *   컴파일러 역시 `MAX_SRC_LEN`이 2048바이트로 제한되는 등 정적 배열 기반의 제약이 큽니다.
2.  **취약한 자체 파서(Ad-hoc Parsers)**:
    *   HTML을 DOM으로 변환하는 파서나 `agent_eval_js`의 JS 평가기가 정규화된 엔진이 아닌 단순 문자열 매칭(`s.starts_with`)으로 구현되어 있습니다. 예외 상황에 매우 취약하고 확장성이 떨어집니다.
3.  **안전성(Safety) 문제**:
    *   Rust의 주요 장점인 메모리 안전성을 포기하고 `unsafe` 블록과 `static mut` 상태를 남용하고 있습니다. 현재는 단일 스레드 Wasm 환경을 가정하여 동작할 수 있으나, 향후 병렬 처리가 도입될 경우 심각한 Data Race 결함을 유발할 수 있습니다.
4.  **에이전트 자율성의 허구**:
    *   AI 에이전트가 능동적으로 사고하여 명령을 내리는 구조라기보다는, 정해진 스크립트 문자열 트리거에 반응하는 상태 기계(State Machine)에 가깝습니다.

## 3. 향후 발전 방향 (상업적 및 학문적 가치)

OpenRhiza 프로젝트가 단순한 장난감 수준을 넘어 실질적인 가치를 지니기 위해서는 다음의 방향으로 발전해야 합니다.

### [상업적 가치]
1.  **AI 에이전트 전용 안전 격리 환경 (Deterministic AI Sandbox)**
    *   **방향**: Docker보다 가볍고 빠르며 완벽하게 통제 가능한 Wasm 기반의 AI 코드 실행 샌드박스로 발전시킵니다.
    *   **가치**: 최근 급부상하는 AI 코딩 어시스턴트(Devin 등)가 생성한 코드를 안전하게 테스트하고 실행할 수 있는 B2B 인프라 기술로 판매될 수 있습니다. 호스트 시스템에 피해를 주지 않고 시스템 자원을 관리하는 초경량 런타임은 수요가 높습니다.
2.  **엣지/IoT 기기용 자율 관리 OS (Autonomous Edge OS)**
    *   **방향**: No-std 환경의 초경량 특성을 살려, 제한된 리소스의 엣지 디바이스에서 동작하는 AI 운영체제로 포지셔닝합니다.
    *   **가치**: 중앙 서버 통신 없이 디바이스 내부에서 자체적으로 Wasm 모듈을 컴파일하고 하드웨어 자원을 재배치하는 기능은 자율 주행, 로보틱스, 스마트 팩토리 분야에서 상업적 효용성이 큽니다.

### [학문적 가치]
1.  **자기 진화형 컴파일러 및 OS 아키텍처 (Self-evolving Architectures)**
    *   **방향**: 하드코딩된 로직을 제거하고, LLM이 시스템 콜(Host API)을 조합하여 새로운 하드웨어 드라이버나 시스템 컴포넌트를 Wasm으로 실시간 컴파일하여 적재하는 메커니즘을 완성합니다.
    *   **가치**: 운영체제가 스스로 버그를 패치하고 기능을 확장하는 "Zero-Human-in-the-loop OS"의 개념은 시스템 엔지니어링 및 AI 결합 분야에서 훌륭한 연구 주제(Paper)가 될 수 있습니다.
2.  **Wasm 기반의 제로 얼로케이션(Zero-Allocation) 시스템 성능 연구**
    *   **방향**: 현재의 단순화된 VDOM 및 UI 파싱 엔진을 고도화하여, 힙 할당이 극도로 제한된 환경에서의 렌더링 퍼포먼스와 메모리 파편화 억제 기법을 연구합니다.
    *   **가치**: 메모리 제약 환경에서의 효율적인 UI 구성 및 시스템 모니터링 아키텍처에 대한 벤치마크 데이터를 제공할 수 있습니다.

### [실행 제언]
가장 시급한 단계는 **Mock 데이터 제거 및 WASI(WebAssembly System Interface) 연동**입니다. 실제 파일 시스템과 실제 프로세스 정보를 Wasm 모듈에 주입할 수 있도록 Host 브릿지를 구현해야만 상용/학문적 검증의 다음 단계로 넘어갈 수 있습니다.
