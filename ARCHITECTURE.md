# Architecture & Evolution

OpenRhiza follows a strict layered architecture and a phased bootstrap scenario to safely evolve from a primitive bare-metal state to an advanced AI OS.

## 5-Layer Architecture

| Layer | Name | Description |
|-------|------|-------------|
| **Layer 4** | **Generative Space** | The ultimate user space. Ephemeral and persistent UIs dynamically generated by the AI based on user intent. Includes the "Nexus" for P2P AI networking. |
| **Layer 3** | **AI Brain Engine** | The entity that writes code and makes decisions. Early on, this relies on an external Host API. Later, it transitions to a completely Local LLM. |
| **Layer 2** | **Advanced Native Drivers** | High-performance modules (GPU, NPU, Storage). Once a driver is validated in the Wasm Sandbox (Layer 0), it is "graduated" (recompiled to native machine code) and dynamically linked here for 100% bare-metal speed. |
| **Layer 1** | **Senses (I/O & Net)** | The AI's first dynamic achievements. Includes scanning the PCI bus to control **USB Host Controllers (xHCI/eHCI)** for input, and networking via **LAN** cards. (PS/2 supported as fallback). |
| **Layer 0** | **OpenRhiza Seed** | The immutable core (`no_std` Rust). Minimal life support: Hardware Abstraction (x86/ARM/RISC-V), Interrupts, **Wasm Sandbox**, Serial Comm, and basic Framebuffer text rendering. |

---

## The 5 Phases of Evolution (Generic Hardware & VMware)

While targeting generic physical CPUs (x86, ARM, RISC-V), we use VMware/QEMU for rapid testing.

### Phase 1: The Seed & Basic Vision
- Booting in a standard x86_64 environment.
- **Layer 0** is active. The Sandbox and Exception Handler (IDT) are set up to prevent kernel panics.
- Communication with the external Host LLM begins via a basic Serial Port (UART).

### Phase 2: Opening the Senses
- The external LLM commands the Seed to probe hardware.
- Through trial and error within the Sandbox, the AI learns to enumerate the PCI bus, successfully writing drivers for **USB Controllers (xHCI)** (Keyboard/Mouse) and a standard Network Interface Card (e.g., `e1000` or Realtek LAN).

### Phase 3: Declaration of Independence
- With LAN secured, the system bypasses the host's serial port.
- It connects directly to the Internet and powerful LLM APIs (e.g., OpenAI, Anthropic) to search for manuals and download massive code snippets.
- **Fallback Mechanism:** If no local GPU/NPU is available, the system can download a quantized, ultra-lightweight LLM to run purely on the CPU memory.

### Phase 4: Muscle Building
- Leveraging external APIs, the system builds complex architecture drivers.
- Validated Wasm drivers are promoted to **Native Kernel Modules** to achieve full control and maximum speed over local Storage and hardware accelerators (GPU/NPU).

### Phase 5: The Ultimate Form
- A Local LLM (small to large-scale) is downloaded and loaded into the GPU/NPU or CPU memory.
- The OS is now completely self-reliant, capable of offline thought, self-improvement, and generative application rendering.
